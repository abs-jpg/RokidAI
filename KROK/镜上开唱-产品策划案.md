# 镜上开唱

Rokid 眼镜 K 歌产品策划案 · v0.1 · 2026 年 11 月 18 日

## 1. 产品定位

**产品名**　镜上开唱  
**应用简介**　戴着 Rokid 眼镜跟伴奏唱歌，实时看音准，唱完看成绩，也能约人唱同一首歌比一比。  
**建议唤起词**　「打开镜上开唱」「我要 K 歌」「开始跟唱练习」

「镜上」说明产品用在眼镜上，「开唱」对应用户最想做的动作。应用首页直接显示选歌列表。

首批面向想练一句歌、听不出自己唱高还是唱低的 Rokid 用户。核心体验是唱到当前歌词时就能看到人声音高与参考旋律的偏差，唱完能找到下一次最值得练的一句。后续用个人成绩、同曲排行榜和双人比赛提供复唱理由。

## 2. 单人跟唱流程

**唤起应用 → 选歌 → 确认并倒计时 → 听伴奏看歌词跟唱 → 查看成绩 → 重唱或保存**

| 页面 | 用户看到什么 | 用户能做什么 |
| --- | --- | --- |
| 选歌 | 歌名、时长与选中状态 | 上下切换，确认进入歌曲。排行榜使用独立入口 |
| 准备 | 歌名、麦克风状态、三秒倒计时 | 确认开始，返回取消。伴奏就绪后进入倒计时 |
| 跟唱 | 顶部当前歌词和计时，中间音准图，底部按键提示 | 对照参考线调整音高，确认提前结束，返回退出 |
| 成绩 | 综合分和等级，音准、演唱覆盖率及最值得重练的一句 | 重唱、保存、返回选歌 |
| 排行榜与个人中心 | 同曲排名、个人最好成绩与历史记录 | 查自己的进步和同曲排名。服务器榜接通前展示本机成绩 |

跟唱时，**当前歌词、计时和实时音准图**始终可见。曲线横轴随伴奏时间推进，纵轴对应音高。参考旋律用较暗的分段线，人声轨迹用亮绿实线。检测不到可靠音高时轨迹断开，连续偏差时短暂强调对应线段，用户能看出自己唱高了还是唱低了。休止和间奏区保留空白。

按 **480×352** 单色绿透明显示设计。左右各留 16 px，上下各留 12 px，内容区 448×328。使用 #40FF5E 的亮度层级、线型和位置区分状态。输入按 Enter 确认、Backspace 返回、ArrowUp 上一项、ArrowDown 下一项实现，在 Studio 用镜腿控件验证对应操作。

对话流中的卡片用于打开应用。完整录音链路放在 `_blank` 承载的页面里。Studio 中唤起应用后，使用「镜腿操作」里的「双击」展开，并在页面的 `onTargetChanged` 中检查切换结果。若音频仍被宿主限制，提示「双击展开后可跟唱评分」，卡片内可继续无声歌词练习。权限被拒绝时显示开启麦克风的提示，提供重试和返回。退出、切回卡片或开始下一次演唱时释放本次的麦克风资源。 [Rokid Target 文档](https://open.rokid.com/aiui/framework/open-agent-format/page/target?lang=zh-CN&version=0.19.0) · [媒体采集限制](https://open.rokid.com/aiui/api/media/media-capture?lang=en-US&version=0.19.0#permissions-and-current-limits) · [Studio 模拟调试](https://open.rokid.com/aiui/guide/debug/web_debug?lang=zh-CN&version=0.19.0)

## 3. 评分规则

| 维度 | 怎么评 | 怎么展示 |
| --- | --- | --- |
| 音准 | 按伴奏时间对齐麦克风基频 F0 和参考 MIDI 音符。仅在应演唱且基频可信的区间计算偏差 | 实时显示唱高或唱低，结束后显示音准分 |
| 演唱覆盖率 | 统计应演唱时段中检测到有效人声的时间占比，排除前奏、间奏和休止 | 显示覆盖率。样本不足时提示「有效演唱不足，再唱一次」 |
| 节奏 | 后续对齐演唱音节或音符的起点，评估进句过早或过晚。用标定样本验证时差估算 | 验证后给出节奏分和具体句子 |
| 歌词匹配 | 后续将识别结果与该版本歌词按句对齐，标记疑似漏唱或错词 | 标注「歌词匹配」。人声识别结果受混音、拖音和唱法影响，待试唱验证后再决定是否纳入正式分数 |

**首版计分**沿用原型的音准表现与演唱覆盖率计算练习分，结果页展示大数字、等级和两项明细。加上按句反馈后，文案可以写「第二句后半段偏低，重唱时试着抬高一点」。音量用于提示收音强弱，歌词匹配用于辅助检查漏唱和错词。无声练习、有效人声不足和提前结束的演唱均不计入正式榜单。排名和对战按相同曲目版本与评分版本比较。

## 4. 内容与技术

### 曲目资产

首版用项目里的《晨光小路》验证 30 秒跟唱。每个可评分的曲目版本应具备同一时间轴上的**纯伴奏、带时间戳的歌词、带起止时间和 MIDI 音高的参考旋律**，同时记录曲目编号、版本、时长、音域和内容来源。开放给用户的曲目采用自制或已取得对应使用授权的素材。

每一版入库前人工走听一次，检查前奏长度、歌词切行、参考音符与伴奏的对应关系。重新混音、移调或剪切后产生新曲目版本，并重新验证对齐。批量扩充曲库留在首版链路验证之后。

### 关键能力

| 功能 | 接口与实现 |
| --- | --- |
| 播放与时间轴 | `AudioPlayer` 播放伴奏。用实际播放进度对齐歌词、参考音符和采样时间 |
| 录音与音高 | 声明 `RECORD_AUDIO`，通过 `navigator.mediaDevices.getUserMedia()` 取麦克风流，并用 `AudioContext`、`AnalyserNode` 读取时域采样和估算 F0。音频上下文可处理声音后开始计算 |
| 实时曲线 | 用 Canvas 绘制参考线和人声轨迹。仅保留屏幕可见的时间窗，避开在每个音频采样点都刷新界面 |
| 个人历史 | 设备本地保存歌曲版本、分数、等级和日期。用户可重唱并查看最好一次的成绩 |
| 歌词匹配 | 使用 `MediaRecorder` 采集用于识别的片段，通过 `SpeechRecognitionSession` 试验歌曲转写。先检查设备支持的输入格式，用不同唱法和伴奏外放录音做小样验收 |
| 服务器榜与联机 | 用 HTTPS 提交成绩、查榜。用 WebSocket 做匹配、准备状态、开唱时间和结算。实时互听使用 WebRTC，在目标设备和实际网络条件下验证 |

## 5. 排行榜与双人同曲赛

### 自建排行榜

第一版服务器榜按单曲列出每位用户的最高有效成绩，并显示「我的名次」。同分时按成绩达成时间排序。成绩记录至少关联用户标识、演唱编号、歌曲版本、评分版本、分数、覆盖率与服务器时间。服务端在入榜前校验身份、版本、演唱资格和分数范围，按演唱编号去重。网络失败时保留本机成绩并明确显示上传状态，允许重试。个人历史记录放个人中心。

封闭测试期验证提交、查榜和防重复。公开竞争前补齐服务端校验和异常成绩处理。单人练习默认只保存结构化成绩。使用外部语音识别或开启对战互听前，向用户说明哪些音频会发送以及发送用途。

### 双人同曲赛

**匹配对手 → 锁定同一曲目版本 → 双方准备 → 按服务器时间倒计时 → 同时跟唱 → 对比成绩**

双方在本地播放同一版伴奏，各自采集和分析自己的人声。由服务端发出统一的开始时间、检查两方提交的场次和评分版本，并汇总结算。演唱时以歌词、计时和自己的音准曲线为主，结算页显示双方分数、结果和再来一局。开唱前可取消匹配，演唱中一方断线则标记对局中断，已完成的个人练习结果可单独保留。

先验证同曲同时比赛和结算，再测试双方可选的实时互听。互听测试重点是跨网络连通率、延迟、回声、对方声漏入本地评分和蓝牙联网场景。互听不可用时保留同曲比赛。

## 6. 开发里程碑与验收

| 里程碑 | 交付内容 | 验收条件 |
| --- | --- | --- |
| P0 · 单人内测 | 《晨光小路》、伴奏、实时曲线、评分、本机成绩 | 在目标眼镜上完成「选歌 → 播放 → 唱 → 看分」。正确音高、故意唱高、故意唱低的固定测试输入能得到对应方向，偏离样本的音准分低于正确样本。拒绝权限、宿主限音、提前退出均有明确提示并能重试 |
| P1 · 成绩与歌词反馈 | 自建单曲榜、个人历史、歌词匹配试验 | 两个账号能看到一致的榜单。重复提交、断网重试均只计一条有效成绩。歌词匹配试唱能区分清楚演唱与明显漏唱，失败时保留原有练习分 |
| P2 · 双人同曲赛 | 匹配、同步开唱、对局结算，随后验证互听 | 两台目标设备能用相同歌曲及评分版本完成一局。双方收到同一结算，取消与断线状态明确。记录开唱偏差和互听延迟，再决定是否扩大内测 |

**首轮可用性目标**　邀请 10 名目标用户各试唱一次，至少 8 人能自行完成练习并看懂音准线。记录从选歌到开始播放的成功率、拿到有效成绩的比例，以及看完成绩后是否愿意再唱一次。数值为内测目标，待实测后调整。

**当前进度**　项目已有《晨光小路》及 Ogg 伴奏、定时歌词、MIDI 参考音符、选歌、音准图、本机评分和本机成绩页。歌词识别、跨设备排行榜与联机仍待接通。Studio 曾出现 `_current` 拒绝音频处理的报错，现有原型能退回无声歌词练习。首个开发验收点是在支持音频的全屏宿主和目标眼镜上实测伴奏、麦克风和评分。
